# Set up Exceptionless

Instructions for a coding agent adding Exceptionless error and event tracking to an app.

## Before you start

- Replace `YOUR_API_KEY` with the API key the user gave you. If they didn't give one, ask for it. It's on the project's API Keys page in Exceptionless.
- Replace `YOUR_SERVER_URL` with the server URL the user gave you. If they didn't give one, leave out the lines that set the server URL, and send REST API requests to `https://collector.exceptionless.io`.
- The API key can only submit events, so it is fine in client code and committed config, like any client SDK key. If the project keeps settings in configuration or environment variables, put the key and server URL there.

## Steps

1. Work out the app's language and framework, and find its section below: ASP.NET Core, Console app (.NET), Worker Service (.NET), Browser JavaScript, Node.js, React, Vue, Angular, React Native, Expo, WPF (.NET), Windows Forms (.NET), REST API (curl), PowerShell, Console app (.NET Framework), ASP.NET MVC, ASP.NET Web API, ASP.NET Web Forms, Windows Forms (.NET Framework), WPF (.NET Framework), or Other languages.
2. Follow its required steps, adapting file names and structure to this project. Do an Optional step when it fits the app, and mention the others to the user.
3. Run the app so it sends the test error "Hello from Exceptionless setup". In browser and mobile apps, put the test error in the entry file right after startup, not in a component. Clients send queued events within about 10 seconds, and on a graceful exit.
4. Check it worked with the section's "Check it worked" step, and wait for that before stopping servers, workers, and browser pages (stop them with Ctrl+C or SIGINT). The API key can't read events back, so a 403 when you try is expected. If you can't run the app or a browser, check the key and server with the REST API example and ask the user to run the app.
5. Remove the test error, the logging you added to check it, and any log file it wrote. Keep everything else.
6. Tell the user what you changed, where the API key lives, and that the test error is waiting for them in Exceptionless.

## ASP.NET Core

.NET. Docs: https://exceptionless.com/docs/clients/dotnet/

### 1. Install Exceptionless.AspNetCore

Run this from your project folder.

```bash
dotnet add package Exceptionless.AspNetCore
```

### 2. Add Exceptionless to Program.cs

Register the client and middleware in Program.cs.

```csharp
using Exceptionless;

var builder = WebApplication.CreateBuilder(args);
builder.AddExceptionless(c => {
    c.ApiKey = "YOUR_API_KEY";
    c.ServerUrl = "YOUR_SERVER_URL";
});
builder.Services.AddProblemDetails();

var app = builder.Build();
app.UseExceptionHandler();
app.UseExceptionless();
```

### 3. Send a test error

Add this after app.UseExceptionless(), run your app once, then remove it.

```csharp
try { throw new Exception("Hello from Exceptionless setup"); } catch (Exception ex) { ex.ToExceptionless().Submit(); }
```

### Optional: Keep settings in configuration

To keep settings out of code, put them in appsettings.json (or Exceptionless__ApiKey environment variables) and call builder.AddExceptionless() with no arguments.

```json
{
  "Exceptionless": {
    "ApiKey": "YOUR_API_KEY",
    "ServerUrl": "YOUR_SERVER_URL"
  }
}
```

### Optional: Send your logs

Send warnings and errors from ILogger too. You can tune log levels per source later from project settings.

```bash
dotnet add package Exceptionless.Extensions.Logging
```

```csharp
builder.Logging.AddExceptionless();
```

### Check it worked

Add c.UseFileLogger("exceptionless.log", Exceptionless.Logging.LogLevel.Debug) to your Exceptionless configuration, then check exceptionless.log. "Sent 1 events" means the server accepted it. builder.AddExceptionless(c => c.UseFileLogger(...)) still reads appsettings.json; for Startup(), call ExceptionlessClient.Default.Configuration.UseFileLogger(...) first.

## Console app (.NET)

.NET. Docs: https://exceptionless.com/docs/clients/dotnet/


### 2. Start Exceptionless and send a test error

Start the client when your app starts. The Submit() line sends a test error so you can see it arrive; remove only that line afterwards.

## Worker Service (.NET)

.NET. Docs: https://exceptionless.com/docs/clients/dotnet/

### 1. Install Exceptionless.Extensions.Hosting

Run this from your project folder.

```bash
dotnet add package Exceptionless.Extensions.Hosting
```

### 2. Add Exceptionless to Program.cs

Register the client in Program.cs. It flushes queued events when the host stops.

```csharp
using Exceptionless;

var builder = Host.CreateApplicationBuilder(args);
builder.AddExceptionless(c => {
    c.ApiKey = "YOUR_API_KEY";
    c.ServerUrl = "YOUR_SERVER_URL";
});
builder.Services.AddHostedService<Worker>();

var host = builder.Build();
host.Run();
```

### 3. Send a test error

Add this just before host.Run(), run your worker once, then remove it.

```csharp
try { throw new Exception("Hello from Exceptionless setup"); }
catch (Exception ex) { host.Services.GetRequiredService<ExceptionlessClient>().SubmitException(ex); }
```

### 4. Send your logs

The host logs a worker's exceptions instead of crashing, so send ILogger warnings and errors to Exceptionless too.

```bash
dotnet add package Exceptionless.Extensions.Logging
```

```csharp
builder.Logging.AddExceptionless();
```

```bash

```

### 2. Start Exceptionless and add the error boundary

Start the client in your entry file and wrap your app in the error boundary to catch render errors.

```javascript
import { Exceptionless, ExceptionlessErrorBoundary } from "@exceptionless/react";
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App";

Exceptionless.startup((c) => {
  c.apiKey = "YOUR_API_KEY";
  c.serverUrl = "YOUR_SERVER_URL";
});

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <ExceptionlessErrorBoundary fallback={<p>Something went wrong.</p>}>
      <App />
    </ExceptionlessErrorBoundary>
  </StrictMode>
);
```

## Angular

JavaScript. Docs: https://exceptionless.com/docs/clients/javascript/

### 1. Install the client

Run this from your project folder.

```bash
npm install @exceptionless/browser
```

### 2. Start Exceptionless and add an ErrorHandler

Start the client in main.ts and route Angular’s errors to Exceptionless with an ErrorHandler.

```javascript
import { ErrorHandler, Injectable } from "@angular/core";
import { bootstrapApplication } from "@angular/platform-browser";
import { Exceptionless, toError } from "@exceptionless/browser";
import { AppComponent } from "./app/app.component";

Exceptionless.startup((c) => {
  c.apiKey = "YOUR_API_KEY";
  c.serverUrl = "YOUR_SERVER_URL";
});

@Injectable()
export class ExceptionlessErrorHandler implements ErrorHandler {
  handleError(error: unknown): void {
    console.error(error);
    Exceptionless.submitException(toError(error));
  }
}

bootstrapApplication(AppComponent, {
  providers: [{ provide: ErrorHandler, useClass: ExceptionlessErrorHandler }]
});
```

## REST API (curl)

Command line. Docs: https://exceptionless.com/docs/api/

### 1. Send a test error

Run this in your terminal. Any language that can make an HTTP request can send events the same way.

```bash
curl "YOUR_SERVER_URL/api/v2/events" \
  --request POST \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data-binary '{"type":"error","environment":"production","@simple_error":{"message":"Hello from Exceptionless setup","type":"System.Exception","stack_trace":"   at Setup.SendTestError()"}}'
```

### Check it worked

A 202 Accepted response means the event was queued. A 401 means the API key is wrong or disabled.

## PowerShell

Command line. Docs: https://exceptionless.com/docs/api/

### 1. Send a test error

Run this in PowerShell to send one error event.

```powershell
$body = @{
  type = "error"
  environment = "production"
  "@simple_error" = @{
    message = "Hello from Exceptionless setup"
    type = "System.Exception"
    stack_trace = "   at Setup.SendTestError()"
  }
} | ConvertTo-Json -Depth 5

Invoke-RestMethod -Method Post -Uri "YOUR_SERVER_URL/api/v2/events" `
  -Headers @{ Authorization = "Bearer YOUR_API_KEY" } `
  -ContentType "application/json" -Body $body
```

### Check it worked

A 202 Accepted response means the event was queued. A 401 means the API key is wrong or disabled.

## Other languages

There are official clients only for .NET and JavaScript. Packages named "exceptionless" in other registries are not ours, so don't install them. Report errors through the REST API instead:

1. Hook the framework's error handler (for example Flask or Django `got_request_exception`, FastAPI `add_exception_handler`, Go `recover` middleware, Rails `rescue_from`). POST each unhandled error to `YOUR_SERVER_URL/api/v2/events` with the headers `Authorization: Bearer YOUR_API_KEY` and `Content-Type: application/json`.
2. Send a body like the REST API example. In `@simple_error`, use the error's message, its class name as the type (for example `ValueError`), and the language's formatted stack trace. Set `environment` from the app's own environment name.
3. Send in the background with a short timeout, and never let a failed send break the app.
4. A 202 response means the event was accepted. Send the test error the same way from a temporary script or route, wait for the response, and log its status while you check.
